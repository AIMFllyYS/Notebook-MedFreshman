# Goal Model 提示词模板

派发"把一批东西同步/生成进某个位置"这类内容任务时用。四段固定结构，缺一不可——尤其是第一、三段，少了它们，AI 大概率会为了省事去写脚本批量套模板（见 `docs/sop/00-infrastructure.md`「内容生产闭环与反降质契约」）。

## 模板

```markdown
# {任务标题}

## 目标
{一句话说清楚要做什么、做到什么程度}

## 先自行分析以下规范（不要跳过，我不会把内容喂给你，你自己读）
- {规范文件 1，如 docs/sop/04-quiz-generation.md}
- {规范文件 2，如 docs/sop/00-infrastructure.md#内容生产闭环与反降质契约}
- {按需再加，通常 2-3 个够用，多了等于没读}

## 涉及位置
- 源材料：{路径}
- 目标位置：{路径}

## 禁令
- 不许写脚本/正则/关键词匹配批量处理这批内容——每一条都要亲自读懂、亲自判断
- 不许把"文件已经写出来"当作"任务完成"，交付前按你刚读的规范自查一遍
- 不许编造源材料里没有的内容
- {本次任务专属的禁令，如术语口径、命名冲突处理方式}

## 需要更新的内容
- {交付物 1 及其路径/规格}
- {交付物 2}
- {如涉及 manifest/registry 等收尾注册，一并列出}
```

## 填写说明

- **"先自行分析规范"不是摆设**：只点名路径，不要把规范内容复述或粘贴进 prompt——逼 AI 自己去读，读的过程本身就是防止它跳过关键约束的第一道闸。
- **"涉及位置"通常就两条**：源材料在哪、目标产出在哪。两条都写具体路径，不要写"相关文件"这种模糊描述。
- **禁令前三条几乎不用改**，是任何内容生产任务的通用红线；第四条按场景补充。
- **"需要更新的内容"要具体到文件路径**，不要只写"完成同步"这种无法核对的目标。

## worked example：同步一批题目进详解章节

```markdown
# 同步概率论第七章题库

## 目标
把这份 Word 题库里概率论第 7 章的题目，转成规范 JSON 写入 content/quiz/probability/ch07.json。

## 先自行分析以下规范
- docs/sop/04-quiz-generation.md（含答案核验/来源目录强制规范、出题→核验闭环）
- docs/sop/00-infrastructure.md#内容生产闭环与反降质契约

## 涉及位置
- 源材料：D:\飞书文档保存\probability\第七章题库.docx（先跑 parse-docs.ts 解析）
- 目标位置：content/quiz/probability/ch07.json

## 禁令
- 不许写脚本/关键词匹配从题库里"提炼"题目或答案，每道题要亲自读懂题干在问什么
- 不许凭记忆判定答案对错，必须 Read content/chapters/ch07/ 对应小节核验
- 出题后必须派独立 Verifier 子智能体逐题复核，有疑义改题，不能自己强行圆
- explanation/sourceRef 不能是空话，必须落到具体知识点和文件位置

## 需要更新的内容
- content/quiz/probability/ch07.json（题目 JSON，字段结构参照 04 号 SOP）
- 若板块能力尚未声明 quiz，检查 lib/content-data/manifest.ts 对应 category
```
